# Add a data page (Next.js 16)

Follow these steps in order. Write the SC-PREFLIGHT note first: the route segment and its existing `page.tsx`, `loading.tsx` and `error.tsx`; the feature's loaders (`data.ts`), DTOs and mappers; the shared table, skeleton and button in `{{sc:sharedComponents}}` (`data-table.tsx`, `table.tsx`, `skeleton.tsx`); the project's page and pagination helpers; and the repository of the entity (`stackcrew-next-typeorm-entity`). Reuse what exists; never add a second table, pager or page shape.

The example is the reviewers' list of eKYC registrations: `src/app/kyc/registrations/page.tsx`, one page of the tenant's registrations, newest first. It reads the entity, constants, messages and repository of `stackcrew-next-server-action`, and the request context of `stackcrew-next-request-logging`.

## 2. Dependencies (ask the user before adding any)

`@tanstack/react-table` for the shared table; the shadcn `table`, `skeleton` and `button` components. The sibling targets TanStack Table v8 (`useReactTable`, `getCoreRowModel()`, `flexRender`, `ColumnDef<Row>`). TanStack Table v9 renamed that API (`useTable` with `features`, `table.FlexRender`, `ColumnDef<Features, Row>`): read the project's `data-table.tsx` and its installed major first, and write the columns for that.

## 3. The loader

```ts
// in data.ts: the page's loader runs the shared query inside the request context of the render
export function loadKycRegistrationPage(query: PageQuery): Promise<ActionResult<PageDto<KycRegistrationRowDto>>> {
  return runInRequestContext(() => listKycRegistrations(query));
}
```

- Data loads on the server, in a `'server-only'` module. A Server Component is not wrapped by a logging wrapper, so its loader runs inside `runInRequestContext(fn)`: the context of the request, built from `auth()` once per render. Without it the tenant repository throws `MissingTenantError`.
- The loader checks the caller through `getRequestContext()`: no user → `UNAUTHENTICATED`, no tenant or no reviewer role → `FORBIDDEN`, before any query. It returns the same `ActionResult` as an action, so the page and a route handler branch on one shape.
- Reads go through the entity's `TenantScopedRepository` (`await kycRegistrations()`): the find and the count both carry the caller's tenant, so another tenant's rows never appear and `total` is the tenant's.
- Every list is paginated: `take`/`skip` from `pageWindow(query)`, `size` capped by `MAX_PAGE_SIZE`, and a stable order with the id as the last key (`{ createdAt: 'DESC', id: 'DESC' }`), so pages never overlap. Past `MAX_PAGE`, use keyset pagination.
- Map entities to row DTOs before they leave the loader: strings, numbers and ISO dates, only the fields the table shows. The document number and the date of birth stay on the server.
- `listKycRegistrations` is shared with `GET /api/v1/kyc-registrations` (`stackcrew-next-route-handler`) and never wrapped itself.

## 4. The page

- `export default async function Page(props: PageProps<'/kyc/registrations'>)`: `PageProps` is generated by `next typegen` (or a build). `await props.searchParams` and read it with `pageQueryOrDefault`: a hand-edited URL falls back to the first page instead of failing.
- `UNAUTHENTICATED` → `redirect()` to sign in, outside any `try`. With `loading.tsx` the response is already streaming, so Next.js sends that redirect as a client redirect (HTTP 200 with a refresh to the target), not a 307. `FORBIDDEN` → the refusal in the page (`role="alert"`). `forbidden()` and `unauthorized()` need `experimental.authInterrupts`; use them only when the project enables it.
- **Empty state:** `total === 0` renders a heading and a short explanation in the page, not an empty table. A later page with no rows (a hand-edited `?page=`) shows the table's own empty row.
- Pagination is links (`?page=n&size=s`, keeping the size the page was read with) styled with the shared `buttonVariants` through `cn()`, inside a `nav` with a label; never a client-side pager over all rows.
- The page reads the session, so Next.js renders it per request. Nothing user- or tenant-specific is cached across users.

## 5. Loading and error

- `loading.tsx` is streamed at once while the page awaits its loader: the page's layout with the shared `Skeleton` placeholders and a `role="status"` text for screen readers. No data, no spinner without text.
- `error.tsx` is a Client Component (`'use client'`) and catches what the page throws: constant text, `error.digest` as the reference (the id `onRequestError` logged), never `error.message`. "Try again" runs `router.refresh()` and `reset()` inside `startTransition`, which fetches the Server Components again and clears the boundary. Next.js 16.0 passes only `reset`; later 16.x releases also pass a retry function that does both.
- Expected refusals are not errors: they come back as results and are rendered by the page. Only unexpected failures (the database is down) reach `error.tsx`.

## 6. The table

- Column definitions hold functions (cell renderers), and a function cannot cross from a Server Component to a Client Component. So the columns live in a `'use client'` component (`KycRegistrationTable`) that the page renders with the rows as props.
- Use the shared table of `{{sc:sharedComponents}}` (`DataTable`, shadcn's data table on TanStack Table) and the shared `Table` components. Never write a `<table>` in a feature. Create `data-table.tsx` from the sibling only when the project has no shared table.
- Dates render as `<time dateTime={iso}>` with an `Intl.DateTimeFormat` of a fixed locale and `timeZone`: the server render and the browser print the same text, so hydration never mismatches.
- Labels, column headers, statuses and the empty texts come from the catalog. The table has a caption (visually hidden) for screen readers.
- `zustand` only for client UI state such as selected rows or open panels, never for the server data.

## 7. Tests

`stackcrew-nextjs-testing` is the full procedure. An async Server Component cannot be rendered by Vitest: test its loader and its client parts there, and the page in Playwright.

- `data.spec.ts`: the page DTO with exactly the row keys and no identity data; `take`/`skip` and the order passed to the repository; the loader runs inside a context built from the session and leaves none behind; `UNAUTHENTICATED` and `FORBIDDEN` before any query; `pageQueryOrDefault` falls back on bad values.
- `kyc-registration-table.spec.tsx` (jsdom): one row per DTO with catalog labels and the UTC date; the empty row.
- `e2e/kyc-registrations-page.spec.ts`: seeded through the app's own form, a reviewer of tenant A sees the row without the document number, a reviewer of another tenant sees the empty state and none of tenant A's rows, an applicant is refused.
- Loading and error states: Playwright can hold the loader (route a slow database in a test environment) or stop the test database to see `error.tsx` and its retry. Tenant isolation itself is proven on Postgres by the entity's persistence spec.

## Do not

- Do not fetch the page's data in a Client Component or through the app's own route handler; load it in the Server Component.
- Do not pass an entity, a `Date`, a class instance or a function from the page to a Client Component.
- Do not return an unbounded list, sort by a column name from the URL, or count without the tenant repository.
- Do not show `error.message`, and do not turn an expected refusal into a thrown error.
- Do not write a second table, skeleton or pager when `{{sc:sharedComponents}}` has one; no `style`, no hardcoded colors.
